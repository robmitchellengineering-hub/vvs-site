Install and use

From nothing to a gate that means something.

One tarball, no dependencies, no network at verify time. If a step here does not work as written, that is a defect — every command on this page is run before it is published.

1 · What you need

Node 18 or newer, and a licence file from your issuer — a signed token beginning vvs1… (a few hundred bytes — it grows only when the issuer includes a revocation list). Without one, valiant gate refuses by design: it will not call a repository fine unless it is licensed to look. Nothing else is downloaded, at install time or at run time.

2 · Install

# install straight from our registry — nothing to ask for
npm install -g "https://api.morpheus.nz/api/functions/getPackage?name=valiant-verification-sdk&version=latest"
valiant --help

valiant licence --file ./acme.licence   # install it, once per machine
valiant licence --status               # what this machine holds: plan, seats, expiry
valiant licence --sync https://vvs.morpheus.nz/revocations.vvs   # pick up the revocation list, now

A licence is monthly — 30 days, the billing period — and renews while the subscription is paid. A failed payment mints a 7-day grace licence, so a declined card does not stop your work the same day. If a licence is revoked, it keeps working for 48 hours with a warning on every run, then stops: a wrong revocation is not meant to become your outage. The last line above is optional — the list also travels inside your next renewal — it is there for the day you need it immediately.

The SDK is not on npm, deliberately — no third-party registry to depend on or be taken over. Distribution is our own registry, and the command above pulls the current build with its checksum. If you would rather have a file: pinned builds with their .sha256, and the index says which version is current.

3 · First run, in five minutes

valiant init      # finds your checks, writes valiant.json — the only file it adds
valiant mutate    # proves the guard it proposed can fail; writes mutations.json
valiant gate      # the verdict

init proposes a first guard only after it has watched it go red: it picks a module your tests import, makes a concrete edit, and runs it through the real mutation engine. If nothing can be proved it says so and proposes nothing, rather than handing you a template that will fail on your first try.

What each verdict word means

wordmeaningwhat to do

7 · What this does not do

  • It cannot tell whether your check means anything. A check that keeps state outside its copy can look like a catch.
  • It is not a security boundary: a check writing outside its copy by absolute path is reported after the fact.
  • It is not a hosted service: no account, no server, no network call. Seats are a local honour system.
  • Scope today: one repository at a time, macOS and Linux. Windows is untested.
  • Not on npm, and no CI service of ours — it produces a verdict; it does not become the queue.
